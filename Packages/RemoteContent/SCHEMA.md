# `formulas.json` and `flags.json`

The two `TR-0.5.2` payloads with no bundled counterpart — `/content/v1/formulas.json` and
`/config/v1/flags.json`. Unlike `exercises.json` (`Packages/SeedContent/SCHEMA.md`), neither is
shipped inside the app; both exist only served, generated at deploy time by
`scripts/generate-remote-content.sh`.

Validate before shipping either:

```swift
let formulaFailures = RemoteFormulasValidator.validate(try Data(contentsOf: formulasURL))
let flagFailures = RemoteFlagsValidator.validate(try Data(contentsOf: flagsURL))
```

An empty result is the only passing result for either.

## `formulas.json`

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "verified": false,
  "rpeTable": {
    "entries": [
      {"repsToFailure": 1, "fractionOfMax": 1.0},
      {"repsToFailure": 1.5, "fractionOfMax": 0.978}
    ],
    "repRangeLowerBound": 1,
    "repRangeUpperBound": 10
  }
}
```

| Key | Type | |
|---|---|---|
| `schemaVersion` | integer | Which *shape* the document is in. A reader refuses a version it does not know. |
| `revision` | integer ≥ 1 | Which *edition* of the content it is. Bumped on every published change, including one that leaves `schemaVersion` alone. |
| `verified` | boolean | Whether `rpeTable` has been checked against a primary publication. `false` for the shipped transcription — see `RPETableStandard.swift`'s doc comment for the full provenance note, which is not repeated here. |
| `rpeTable` | object | `RPETable`'s own wire shape (`entries`, `repRangeLowerBound`, `repRangeUpperBound`) — see that type's doc comment in `PowerliftingCore` for what each guard rejects. |

Two version numbers for the same reason `exercises.json` has two: one field cannot answer both
"can this reader read it" and "is there anything newer".

## `flags.json`

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "minimumSupportedVersion": "1.0.0"
}
```

| Key | Type | |
|---|---|---|
| `schemaVersion` | integer | Same role as `formulas.json`'s. |
| `revision` | integer ≥ 1 | Same role as `formulas.json`'s. |
| `minimumSupportedVersion` | string, non-blank | The lowest app version still allowed to run (`TR-0.5.4`). Not parsed or compared by this package — see `RemoteFlags`'s doc comment for what is and is not this payload's job. |

## What is not here

Neither payload rejects an unrecognised key the way `exercises.json` does — that guard exists
there because a hand-authored catalogue of eighty-plus entries is where a typo is likely to hide a
missing fact. Both of these documents are machine-generated by `GenerateRemoteContent`, which
cannot typo a key it does not spell by hand.
